제품을 만들고,
사업의 결과까지 확인하기

AISU는 수어 사전과 커뮤니티를 함께 제공하는 서비스입니다. 공동창업자로서 문제 정의와 제품 기획, 개발팀 리딩, Android 구현을 맡았고, 예비창업패키지 최우수 통과와 B2B 계약을 통한 실매출까지 제품의 결과를 사업 성과로 연결했습니다.

PROJECT

기술 구현 전에 서비스의 사용자를 먼저 정의했습니다.

수어 통역사 부족과 수어 데이터의 파편화라는 문제에서 출발했습니다. 수어 사용자를 위한 사전·검색·커뮤니티를 만들되, 글자를 읽는 데 익숙하지 않은 사용자도 사용할 수 있어야 했습니다.

코파운더로서 제품을 기획하고 팀을 이끌어 서비스를 출시했고, 최우수 통과·B2B 계약·실매출이라는 결과를 이끌어냈습니다.

KotlinJetpack ComposeExoPlayerWebView Bridge멀티 모듈

PROBLEM

사용자가 겪던 세 가지 문제

문제 · 흩어진 수어 데이터

지역과 국가에 따라 수어가 달라 사용자가 원하는 표현을 찾기 어려웠습니다. 직접 촬영한 영상과 기존 데이터를 함께 구성해 사전과 검색에서 필요한 표현을 찾을 수 있게 했습니다.

문제 · 글자를 중심으로 한 UI

한글이나 영어를 읽는 데 익숙하지 않은 사용자에게 텍스트 중심 화면은 진입 장벽이었습니다. 상징적인 마크와 짧은 단어 중심으로 화면을 기획해 정보를 이해하는 단계를 줄였습니다.

문제 · 영상 서비스의 데이터 부담

커뮤니티의 영상이 자동 재생되면 데이터 사용량과 대기 시간이 커질 수 있었습니다. 캐싱과 재생 최소화를 적용하고, 앱에서는 사용자가 터치한 영상만 재생하도록 했습니다.

제품으로 해결한 결과
세 가지 문제를 해결하는 서비스를 실제로 출시했고, 예비창업패키지 최우수 통과와 B2B 계약을 통해 실매출을 이끌어냈습니다.

PROBLEM & SOLUTION

문제를 정의하고 구조로 해결한 방식

Player가 화면에 남는 문제

검색어 랭킹을 구현하며 LazyColumn 안에 Player를 직접 배치했을 때, 화면을 이동한 뒤 이전 영상의 잔상이 남고 재생 상태가 꼬였습니다. 수어 사전처럼 영상이 많은 화면에서는 리스트와 Player의 생명주기를 분리해서 관리해야 했습니다.

UiState와 ViewModel로 상태 분리

화면 전환 시 UiState에 Empty 상태를 두고 기존 Player 리스트를 먼저 제거했습니다. ExoPlayer 객체는 외부 ViewModel에서 리스트로 관리해 각 Composable이 자신의 화면 상태와 Player 상태를 섞지 않도록 해결했습니다.

잦은 UI 변경과 빠른 배포

초기 서비스는 화면과 콘텐츠를 자주 바꿔야 했습니다. 커뮤니티와 홈 화면은 WebView로 구현해 빠르게 수정·배포할 수 있도록 하고, 네이티브 앱에는 꼭 필요한 기능만 남겼습니다.

앱과 웹을 연결하는 브릿지

WebView 안에서도 카메라와 로그인 같은 앱 기능을 사용할 수 있도록 앱과 웹 사이의 Bridge 인터페이스를 설계하고 세팅했습니다. 호출 가능한 기능과 이벤트, 데이터 전달 방식을 정리해 두 환경이 안정적으로 통신하도록 구성했습니다.

핵심은 기술을 나누는 기준을 세운 것
영상 재생처럼 네이티브 제어가 중요한 영역은 상태를 분리해 안정성을 확보하고, 변화가 잦은 화면은 WebView와 브릿지로 빠르게 실험할 수 있게 했습니다.
