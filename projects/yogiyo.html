많은 사용자가 쓰는 앱을

요기요 Android 앱에서 로그인·회원가입·주문내역·주문상세·요마트 등의 화면을 단계적으로 Compose로 전환하고, 콜드 스타트와 화면 진입 과정의 ANR 원인을 분석했습니다. AI 도구와 리소스 관리 흐름도 직접 고쳤습니다.

PROBLEM MAP

새 화면보다 어려운 건
운영 중인 앱을 안전하게 바꾸는 일이었습니다.

운영 중인 앱에서는 화면을 한 번에 갈아엎을 수 없습니다. 기존 XML 화면과 새 Compose 화면을 함께 운영해야 하고, 사용자에게 노출되는 시점도 피처 플래그와 Remote Config로 조절해야 합니다.

그래서 성능 문제는 원인을 관측할 수 있게 만들고, 화면 전환은 되돌릴 수 있는 단위로 나누며, 반복 작업은 도구로 줄이는 방향을 선택했습니다.

01 / 안정성

ANR 원인을 추적하고
다음 문제까지 볼 수 있게

문제 · 메인 스레드가 오래 점유됨

콜드 스타트와 화면 진입 중 컴포넌트 매핑, 리스트 diff, Keystore 접근, asset 파싱, deviceId 조회가 메인 스레드를 오래 점유했습니다. 사용자에게는 화면이 멈추거나 늦게 열리는 문제로 보였습니다.

해결 · 원인을 옮기고 관측 지점을 남김

작업을 백그라운드로 이동하고, 메인 스레드 정체를 다중 샘플링하는 ANR 리포터와 종료 사유·화면 breadcrumb Datadog 기록을 추가했습니다.

콜드 스타트

FrontyoV2 컴포넌트 매핑을 Default 디스패처로 이동하고 Keystore 초기화를 지연시켜 첫 화면 진입을 막는 작업을 줄였습니다.

화면 진입

Groupie Section diff와 iLog config asset 파싱을 메인 스레드 밖으로 분리해 화면 진입 중 정체 구간을 줄였습니다.

해결 결과

ANR 종료 사유와 화면 breadcrumb를 남겨 오류 한 건을 닫는 데서 끝나지 않고 다음 문제를 재현할 수 있는 기반을 만들었습니다.

02 / 화면 전환

여러 화면을
한 번에 깨뜨리지 않고 바꾸기

문제 · XML과 Compose를 동시에 운영해야 함

로그인·회원가입·아이디/비밀번호 찾기부터 주문내역·주문상세·요마트까지 한 번에 전환하면 사용자에게 노출되는 위험 범위가 너무 커졌습니다.

해결 · 화면 단위 전환과 플래그 경계

화면별 피처 플래그와 Remote Config로 전환 시점을 조절하고, 공용 입력 컴포넌트와 기존 View 계층 연결 지점을 정리했습니다.

  • 로그인·회원가입·아이디/비밀번호 찾기: `feature:login`과 공용 입력 컴포넌트 정리
  • 주문내역·최근 주문상세·요마트 상품/카테고리: 화면 단위 Compose 전환
  • 글로벌홈·샵리스트 개편: Compose와 기존 View 계층 연결
  • 하단 네비게이션 겹침, 글자 크기 확대, 상태바 겹침 등 전환 과정의 UI 문제 대응
해결 결과
Compose 적용 화면을 늘리면서도 기존 XML 화면을 함께 운영할 수 있는 전환 단위를 만들었습니다. 화면 수보다 중요한 성과는 문제가 생겼을 때 특정 화면만 되돌릴 수 있게 한 것입니다.

03 / 모듈화

화면 전환을 막는 의존성도
함께 정리하기

문제 · 기능 경계가 흐려짐

기존 app 모듈과 feature 사이의 직접 의존이 남아 있으면 화면을 옮길 때 수정 범위가 커지고, Compose 전환도 특정 기능에 묶이게 됩니다.

해결 · 공용 계층과 기능 경계 분리

공용 UI와 로그인 기능의 위치를 옮기고 feature 간 의존을 core를 경유하도록 바꿔 화면 전환의 영향 범위를 줄였습니다.

공용 계층

app 모듈의 BaseActivity와 adapter 계층을 core:presentation으로 옮겨 공용 UI를 한 곳에서 관리했습니다.

로그인 기능

로그인 잔여 코드와 LoginNavigatorImpl을 feature:login으로 이동해 기능의 책임을 분리했습니다.

직접 의존 제거

feature 간 직접 의존을 core를 경유하도록 바꾸고 data 루트의 domain:search 의존도 정리했습니다.

해결 결과

화면 전환에 필요한 코드의 위치와 의존성 경계를 정리해 다음 Compose 전환이 기능 전체를 흔들지 않도록 기반을 만들었습니다.

빌드 툴체인에 대한 판단
전체 Compose 전환 이후 빌드 시간 개선을 위한 KSP 전환에 대비해, 전환 가능한 영역은 단계적으로 옮기고 DataBinding 때문에 남은 kapt 의존성을 정리했습니다.

04 / 개발 흐름

반복 작업을 줄여
개발자가 문제 해결에 집중하게 하기

문제 · AI 도구의 컨텍스트 낭비

자동 코드 리뷰 훅이 메인 컨텍스트를 불필요하게 다시 읽고, 빌드 로그와 diff 전문이 작업 흐름을 가리는 문제가 있었습니다.

해결 · 실행 경계와 리소스 흐름 정리

실행 로직과 스킬을 정리하고, 번역 데이터를 Android 리소스 형식으로 바꾸는 AI 기반 관리 도구와 작업 흐름을 만들었습니다.

해결 결과
AI를 도입했다는 사실보다 개발자가 매번 확인하고 복사하던 작업을 줄이고, 실패했을 때 다시 확인할 수 있는 경계를 만든 것이 성과입니다.
